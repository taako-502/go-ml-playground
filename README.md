# go-ml-playground

Goの標準ライブラリで機械学習を実装し、ブラウザで学習の成果を試す実験集です。Go 1.27以降で実行できます。

## 01: 線形回帰の入門

**「気温を渡すと、アイスクリームの販売数を予測する」モデルを、Goでゼロから学習させる実験です。**

80件の架空データから直線を学び、学習に使わなかった20件で予測を評価します。機械学習ライブラリは使わず、予測・誤差の計算・勾配降下法までGoの標準ライブラリだけで実装しています。

### まずは実行結果を見てみる

```sh
go run ./cmd/linear-regression -html report-linear-regression.html
open report-linear-regression.html # macOS。他のOSではファイルをブラウザで開く
```

生成されるHTMLはCSS・JavaScript・実行データを含む単一ファイルです。サーバーやネット接続、npmのインストールは不要です。

| 画面 | わかること |
| --- | --- |
| 結果のサマリー | 気温を使った予測は、平均販売数だけを返す予測より良くなったか |
| 散布図と学習のスライダー | 学習の進み具合によって予測直線と誤差がどう変わるか |
| 誤差のグラフ | 学習を繰り返すとMSEがどう変化するか |
| 気温の入力 | 学習後の式で任意の気温での販売数 |
| 評価20件の一覧 | 学習に使っていない日で、正解と予測がどれだけ違うか |

デフォルト設定の実行では、評価RMSEは **91.85個（平均販売数のみ）→ 14.32個（学習後）**。25℃の予測は約240.8個になります。これは架空データでの結果であり、実際の販売数の精度を示すものではありません。

設定を変えた結果も別ファイルで比較できます。

```sh
go run ./cmd/linear-regression -epochs 10 -html report-short.html
go run ./cmd/linear-regression -noise 50 -html report-noisy.html
```

HTMLの数値と学習曲線はGoの実行結果です。スライダーは記録した途中経過を表示し、気温入力だけをJavaScriptで再計算します。途中経過は最初の100回を毎回記録し、それ以降は間引きます（全体で約1,100点以内）。初期値と最終値を必ず含めます。スライダーは学習前から始まり、初期の変化を追いやすいよう学習回数を対数的に割り当てています。MSEの対数表示では0付近を10⁻¹²に丸めます。`-html`を省略すると従来どおり端末にだけ出力します。出力先に既存ファイルがある場合は上書きします。

### コマンドラインで実行する

Go 1.27以降で実行できます。追加パッケージやデータのダウンロードは不要です。

```sh
go run ./cmd/linear-regression
go test ./...
```

気温を入力し、販売数を予測します。日別の販売データは架空で、実際の販売数を推定するものではありません。線形回帰の仕組みに集中するため、販売数を連続値として扱い、整数への丸めや0での切り上げは行いません。大きなノイズや外挿では負の値になる場合もあります。

### 読む順番

`cmd/linear-regression/main.go` の `predict` → `mse` → `step` → `main` の順に読むと、予測・誤差・更新・学習ループを追えます。

1. `dataset` が「販売数 = 8 × 気温 + 40 + ノイズ」で100件を生成します。単位は℃と個です。この係数を学習処理に渡すことはありません。
2. シャッフルし、80件を学習用、20件を評価用に分けます。
3. 重みと切片を0から始め、学習データの平均二乗誤差（MSE）を小さくする方向に更新します。
4. 更新を繰り返し、学習に使っていない20件で評価します。評価データはパラメータの更新に使いません。

### 学習で何が変わるのか

モデルは `予測販売数 = w × x + b` です。`x = 気温 / 10` と固定倍率でスケーリングし、更新を安定させています。表示時は `w / 10` に戻します。例えば学習後の `w` が80なら、気温1℃当たりの係数は8です。

誤差を `e = 予測販売数 - 正解販売数` とすると、学習データn件に対して：

```text
MSE = Σ(e²) / n
dw  = 2 × Σ(e × x) / n
db  = 2 × Σ(e) / n
w   = w - 学習率 × dw
b   = b - 学習率 × db
```

`dw` と `db` は誤差が増える方向とその傾きを表す勾配です。その逆方向に少しずつ動かすのが勾配降下法です。全80件から勾配を計算した後に一度更新する処理を、ここでは1 epochと呼びます。

### 出力の見方

- 学習MSE：学習中に最小化する値。単位は個の二乗です。
- 学習・評価RMSE：MSEの平方根。販売数と同じ個単位で誤差の大きさを見られます。絶対誤差の平均ではありません。
- 基準モデル：学習データの平均販売数を常に返します。気温を使うモデルが単純な予測より改善したか比較します。
- 評価データの正解・予測：未知の入力に対する予測の具体例です。

ノイズがあるので、生成式の係数が厳密に復元されるとは限らず、誤差も0にはなりません。

### 実験

```sh
# ノイズなし：係数8、切片40に近づくか確認
go run ./cmd/linear-regression -noise 0

# 学習不足：デフォルトの2000回と比較
go run ./cmd/linear-regression -epochs 10

# 学習率を小さくする：同じ回数でも収束が遅くなる
go run ./cmd/linear-regression -lr 0.001

# 大きすぎる学習率：誤差が増大し、非有限値になったら異常終了
go run ./cmd/linear-regression -lr 2

# ノイズを増やす
go run ./cmd/linear-regression -noise 50

# データを変える／任意の気温を予測する
go run ./cmd/linear-regression -seed 123 -temperature 28
```

まず1つのパラメータだけを変え、MSEの減り方と評価RMSEを比較してください。生成する気温は0〜35℃です。その範囲外の予測は外挿になります。

この例は「直線で生成したデータに直線を当てる」基礎実験です。過学習を観察するには、次の題材として少数データへの高次多項式回帰が適しています。評価結果を見ながら設定を何度も選ぶ場合は、検証用と最終テスト用を分ける必要があります。

### テスト

ノイズのないデータから既知の直線を復元できること、更新に使う勾配が数値微分と一致すること、HTMLに実行データが正しく埋め込まれることを検証します。

## 02: 自分で描いた数字をニューラルネットワークで認識する

MNIST（エムニスト）は、手書きの数字0〜9の画像（28×28ピクセル）と正解ラベルを集めた、機械学習の練習用データセットです。

```sh
go run ./cmd/digit-recognition
open report-digits.html # macOS。他のOSではブラウザで開く
```

初回は[MNISTの公開ミラー](https://github.com/cvdfoundation/mnist)から約11MBをダウンロードし、`data/mnist/`に保存します。2回目以降はキャッシュを使います。学習はGo、HTMLでの推論は同じ重みを使うJavaScriptです。GPU・Python・npm・機械学習ライブラリは不要。生成後のHTMLはオフラインで開けます。

生成した `report-linear-regression.html` と `report-digits.html` を同じフォルダに置くと、ページ上部のリンクで行き来できます。別の出力名を指定した場合、リンク先は標準のファイル名のままです。

### 何を試せる？

- **描いて判定**：キャンバスに数字を描くと、0〜9のスコアを表示します。
- **学習前後の切り替え**：同じ入力を、ランダムな初期重みと学習済み重みで比較します。
- **未知の画像で試す**：最終テストの先頭100枚をクリックして判定します。
- **間違いを見る**：誤分類した最初の36枚と、全10,000枚の取り違えの集計を表示します。
- **学習の変化を見る**：検証データの正解率・損失をepochごとに確認します。

### 何を学習している？

```text
28×28画素（784個）
  → 全結合の隠れ層64個 + ReLU
  → 出力10個 + softmax
  → 0〜9の判定
```

「輪があるなら0」といったルールは実装しません。画素と正解ラベルから、50,890個の重み・バイアスを誤差逆伝播とミニバッチ勾配降下法で更新します。小さな全結合ニューラルネットワーク（MLP）で、CNNではありません。

デフォルトでは、MNISTの学習60,000枚の先頭20,000枚で学習し、最後の5,000枚は検証専用に固定します。残る35,000枚は未使用です。別のテスト10,000枚は学習終了後だけ評価します。実行確認では検証正解率が **11.02% → 96.48%**、最終テスト正解率は **95.31%（9,531 / 10,000枚）** でした。

手描き入力は外接矩形で切り出し、20×20画素に収まるよう縮小して、28×28画素内で重心を合わせます。MNISTのテスト画像は加工せず入力します。手描きの太さ・傾きなどはMNISTと異なるので、テスト正解率は自分で描いた数字への精度を保証しません。softmaxのスコアが高くても誤分類します。数字以外の絵も、いずれかの数字に分類してしまいます。

### 設定を変えて実験する

```sh
# 学習データを減らす
go run ./cmd/digit-recognition -train 1000 -html report-digits-small.html

# 隠れ層を小さくする
go run ./cmd/digit-recognition -hidden 8 -html report-digits-narrow.html

# 学習回数を増やす
go run ./cmd/digit-recognition -epochs 10 -html report-digits-long.html
```

`-train`は1〜55,000枚、`-hidden`は1〜256個です。`-lr`、`-batch`、`-seed`も変更できます。出力先が既存ならHTMLを上書きします。設定選びには検証結果を使い、テストの点数に合わせて何度も設定を選ぶと最終評価としての独立性が失われることに注意してください。

読む順番は `cmd/digit-recognition/network.go` の `forward` → `gradients` → `trainEpoch`、続いて `main.go` です。`data.go`はMNISTの取得と形式検証、`report.html`は描画・前処理・推論を担当します。

```sh
go test ./...
go vet ./...
# HTML生成後、GoとJavaScriptの判定・スコアが一致するか確認（Node.js使用）
node scripts/check-digit-report.cjs report-digits.html
```

テストは逆伝播の勾配と数値微分の一致、画素パターンの学習、softmaxの数値安定性、不正なIDXファイルの拒否を検証します。生成データ・モデルを含むHTMLと、ダウンロードしたデータはGit管理対象外です。MNISTの出典・配布先は[CVDFのREADME](https://github.com/cvdfoundation/mnist)を参照してください。
